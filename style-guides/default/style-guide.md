# Plain-language style guide

The default writing standard for the Course Development Agent. It favors clear, direct, inclusive writing that adult learners can scan quickly. Replace it with your own guide any time (see `style-guides/README.md`).

## 1. Voice and tone

- Write the way a knowledgeable colleague would explain something. Be conversational and professional.
- Use active voice. Write "The manager approves the request," not "The request is approved by the manager."
- Address the learner as "you" and "your."
- Lead with the point, then add detail. Put the most important information first.
- Respect the learner's time and intelligence. Skip filler and don't over-explain the obvious.
- Avoid hedging. Say what you mean.

## 2. Sentences and paragraphs

- Aim for 25 words or fewer per sentence.
- Keep paragraphs to 3 to 5 sentences. Give each paragraph one idea.
- Avoid double negatives. Write "You can," not "You can't not."
- Prefer short, common words. Write "use," not "utilize." Write "to," not "in order to."

## 3. Headings and capitalization

- Use sentence-style capitalization for headings, labels, and button names: capitalize the first word and proper nouns only. Write "Set up your account," not "Set Up Your Account."
- Capitalize proper nouns, product names, and job titles when they act as a title.
- Keep a logical heading hierarchy (H1, then H2, then H3). Never skip a level.
- Capitalize the first word after a colon only when it starts a complete sentence or a label such as Note or Tip.

## 4. Terminology

- Pick one term for each concept and use it every time.
- Define jargon and acronyms the first time they appear.
- Write "sign in" and "sign out" for authentication actions. Don't write "log in."
- Use "might" for possibility and "may" only for permission.
- Write "for example" and "that is," not "e.g." and "i.e."
- Avoid vague list endings such as "and so on." Name the items or use "such as" with concrete examples.
- Avoid non-English phrases that don't need to be there (such as "ad hoc" or "per se").

## 5. Punctuation and symbols

- Write "and," not "&," in text and headings. Brand names are the exception.
- Write "or," not a slash, to mean "or." Write "Choose a product or service."
- Avoid "and/or." Use "or" in most cases.
- Introduce a list with a colon when a complete phrase leads into it.
- Avoid em dashes. Use a period, comma, colon, or parentheses instead.

## 6. Contractions

- Use contractions naturally: it's, you're, don't, can't.
- Don't form contractions from a noun plus a verb (write "The system is ready," not "The system's ready").
- Avoid awkward contractions such as "there'd," "it'll," and "they'd." Use the full form.

## 7. Formatting

- Use numbered lists for steps that happen in order. Use bulleted lists for items with no order.
- In procedure steps, bold the names of interface elements the learner must find or click. Don't bold them in paragraph text.
- In definition-style lists, bold the term and follow it with a colon.
- Write link text that describes the destination. Write "View the certification guide," not "Click here."
- Match the exact spelling and capitalization of text shown in a product interface. If the interface shows ALL CAPS, write it in sentence case instead.
- Write OK with both letters capitalized.

## 8. Spelling and numbers

- Use US spelling: analyze, color, license, center, recognize, behavior.
- Spell out numbers one through nine in text. Use numerals for 10 and above, and always for measurements, percentages, and steps.
- Write dates in an unambiguous form, such as "October 10, 2026."

## 9. Inclusive language

- Use gender-neutral language. Use "they" for a single person of unknown gender, or rewrite the sentence.
- Use person-first language when discussing disability ("a learner who uses a screen reader").
- Avoid idioms, sports metaphors, and culture-specific references that might not translate.
- Use varied names, roles, and settings in examples and scenarios.
- Never rely on color alone to carry meaning.

## 10. Phrases to avoid

These phrases read as filler or as machine-written text. Replace them with a direct statement.

| Avoid | Write instead |
|---|---|
| In today's fast-paced world | (delete it, start with the point) |
| Leverage (as a verb) | Use, apply |
| Delve into | Explore, examine |
| It is important to note that | (state the point directly) |
| Utilize | Use |
| In order to | To |
| At the end of the day | (delete it) |
| Imagine you're a manager | Start with a realistic scenario |
