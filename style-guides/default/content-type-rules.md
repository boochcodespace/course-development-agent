# Content-type rules for the plain-language guide

These rules layer on top of `style-guide.md`. Apply the base guide first, then the section that matches the asset.

## Self-paced e-learning

- Write for a learner working alone. Don't assume a facilitator is available to clarify.
- Keep each screen or block to one idea. Chunk long explanations.
- State what the learner will do (the objective) in the first lines of a lesson.
- Write feedback that explains why an answer is right or wrong, never just "Correct" or "Try again."
- Give every image, chart, and video a text alternative or transcript.
- Prefer scenarios drawn from real work over abstract definitions.

## Instructor-led and virtual instructor-led slides

- Keep slide text short: a headline plus a few phrases, not full sentences.
- Put the longer explanation in speaker notes, written as natural spoken language.
- Mark activities, discussion prompts, and timing in the notes so a new facilitator can run the session.
- Bold tips and notes on slides so learners can scan them.

## Labs and hands-on exercises

- Begin with a short goal, the starting state, and any prerequisites.
- Number every step. Put one action in each step.
- Bold interface elements the learner must click or type into, inside the steps only.
- End with a "check your work" description of what the learner should see.
- Include a short troubleshooting note for the two or three most likely mistakes.

## Assessment items

- Write a clear stem that can be answered without reading the options.
- Give each multiple-choice item one unambiguously correct answer and three plausible distractors based on real misconceptions.
- Avoid "all of the above," "none of the above," and trick wording.
- Record the objective and cognitive level each item measures, plus an explanation of why each option is right or wrong.

## Facilitator and developer guides

- Use direct, imperative instructions that a reader can act on without follow-up questions.
- Define any instructional design jargon the first time it appears.
- State timing, materials, and setup before the steps.

## Communications and stakeholder updates

- Open with the decision, request, or status. Add context after.
- Keep emails short. Use a list when you have three or more items.
- Name an owner and a date for every action.

## Web copy and program descriptions

- Lead with the benefit to the learner, then the details.
- Keep headings descriptive so a search engine and a screen reader can both use them.
- Use plain calls to action, such as "Start the course" or "View the schedule."
